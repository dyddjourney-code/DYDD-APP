# Circles operations API (sandbox only)

`GET /api/circles/operations` authenticated: `{circles, approvals, limits}`. Cards are participant-safe for accepted members; creators receive management detail. `?circleId=UUID` returns `{circle, role, lifecycle, members, callouts, consents, rosterPreviews}`. Owner verified by server `DYDD_CIRCLES_OWNER_USER_IDS` (comma-separated UUIDs), never user metadata; owner gets approvals. Private owner-preview GET returns existing preview circles, POST operational actions requires actual verified account.

`POST /api/circles/operations` same-origin JSON `{action,circleId,...}`. Actions:
- `request_cohort`: `circleId, organization,purpose,enrollment,launchDate,details`; deduplicates pending same-circle requests; persisted held owner-email outbox. `approve_cohort`: owner only, `requestId,seatCap` (>= requested enrollment). `set_limits`: owner only `userId, daily,monthly,burst,inviteDaily,inviteBurst`.
- `preview_roster`: `circleId,csv` (header `name,email`, quoted CSV supported); returns `previewId,rows,errors,duplicates,canInvite`. Nothing sent. `invite_roster`: `circleId,previewId`; revalidates capacity/payment/lifecycle and consumes quotas transactionally, persists email-bound expiring invitations plus held sandbox outbox. `invite`: `circleId,name,email` one person. Invitations reserve seats. Invite URLs appear only in creator held outbox, never sent live.
- `accept_invite`: `token`; verified signed-in email must match, active personal entitlement required; no leadership purchase. `decline_invite`: `token`; `leave`: `circleId`; `revoke_invite`: `membershipId,circleId`.
- `consent`: `circleId,people:boolean,insights:boolean` explicit opt-in, revoke anytime. People roster projections never expose emails. Insights consent does not publish private reflections.
- `callout`: `circleId,session,lesson,prompt,marked:boolean,shareText:boolean,text?,audience:"leader"|"circle"`; explicit opt-in text only Small/Class (Couple permitted), Cohort rejects all text. `withdraw_callout`: same keys. Summary counts DISTINCT accepted user per session/lesson/prompt; Cohorts counts only. Participant sees own text and circle-audience shared text only. Leader sees explicitly leader/circle shared text only. No private reflection access.
- `transfer`: `circleId,toUserId`; creator during full/transition only; new leader must be accepted and personally/leadership subscribed. Couples transfer unsupported. `set_role`: creator `membershipId,role:"participant"|"facilitator"`; facilitator does not grant billing or private access.

Creation remains `POST /api/circles` and now includes persistent database enforcement (30/day,60/month,5/10minutes account defaults, counts survive archive/delete).
