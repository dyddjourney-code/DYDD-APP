DESIGNPD REPORT MIGRATION AUDIT — October 15, 2026

State: diagnosis complete; no production changes, report generation, email or pricing changes.

Confirmed findings:
1. The app report builder does not use the eight established source narrative libraries. It uses newly authored generic axis text and templated reflection sentences instead. Correct numeric scoring does not establish report parity.
2. All 45 practical-application fields (five areas x three axes x strength/watch/growth) are filled from only 15 generic sentences. Within each area, Plan/Decide/Do receive identical copy, independent of tendency. Source lookup must be Area|Axis|Tendency_Type.
3. Primary reflection overlays and secondary reflection modulators do not select the source text. The current secondary modulator is selected by axis tendency rather than the secondary reflection.
4. The 12 reflection/axis amplifier paragraphs are static, rather than selected by Axis|Reflection|Bandwidth_State. All four reflection capacity bands must participate.
5. Integrative lens and shadow-watch text are interpolated stand-ins, not the source Integrative_Shadow_Library entries. Reflection_Shadow and Shadow_Reflection are currently set to the same value, although the source provides separate fields.
6. The published and draft PDFMonkey template place six score dots with left:calc(50% - {{movement}}). App movements are unitless fractions, so nonzero values produce invalid CSS. Chromium CSS.supports rejects calc(50% - 0.14) and accepts calc(50% - 14%). The score polarity, proper scale, center, rail insets and boundaries must be checked against the established website report before choosing the final rendering fix.
7. The app native snapshot profileLanguage stores only three generic core strings plus a shadow label; it does not retain the fully resolved report payload/content version. Auditability should include the exact resolved report content and source version.
