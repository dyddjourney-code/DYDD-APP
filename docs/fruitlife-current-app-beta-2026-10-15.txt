FRUITLIFE 360 — CURRENT APP BETA RESTORATION
October 15, 2026

Goal
Start and run FruitLife360 inside the main DYDD app, not the older mini-app lane.
Keep the existing course. Do not change old completed reports or old Sheet/Make workflows.

Findings
- Current-app Start Assessment reached a setup endpoint gated by the old per-run entitlement; failed access redirected into lane=fruitlife, hiding the main app navigation.
- Setup returned to the older entry gate rather than opening the reflection.
- Cancelled observer tokens remained accepted; cancellation did not reduce the completion requirement.
- Reminder fallback could resend completed/cancelled invitations.
- Thank-you copy claimed report/email completion while waiting for observers.
- Observer tokens could read the participant roster/status; report downloads lacked ownership checks.
- Repeated submissions used random source IDs and could create duplicate responses.
- Worker retries created new PDFs; failed final-email artifacts prevented retry; stale processing locks were not recovered.
- Native report engine used simplified guidance and pooled self/observer ranking, unlike the original source formulas. Many original item statements were rewritten.

Implemented
- Main app setup and Field Kit continue flow. Main-app beta access follows the same signed-in pattern as DesignID; it does not require/consume the old $10 tripwire purchase. No Stripe product or subscription settings were changed.
- Participant identity is tied to the signed-in account; up to 12 distinct named observers; goal derives from actual invitations. Setup opens the self reflection immediately.
- Browser-local draft save/resume for ratings, ranking, step and notes, scoped to session/token/role; saved drafts cleared on submission confirmation. Not cross-device answer syncing.
- Stable response IDs, strict server-side item/rank/reflection validation, role-specific tokens, cancelled/completed link rejection.
- Completion totals rebuilt from persisted responses; cancelling an unfinished invite updates the required count and queues the report when appropriate. Pending-only reminders, truthful provider feedback.
- Participant-only status access and owned/admin report access. Observers can submit without buying anything or creating an account, but cannot read another observer's details or the participant report.
- Background after-response report worker; stored PDF provider IDs reused on retries; failed email retried; already-sent deduplication/idempotency key; stale-lock recovery. Existing historical ready jobs are not swept into a new email run.
- Original workbook scoring: observer consistency first, self consistency tie-break, then canonical fruit order; self-only uses own consistency scores. Forced ranking is preserved separately, not substituted for the source formula.
- Original 36 scored item texts for self and observer restored; saved instrument/scoring versions and complete item definitions on new responses.
- Source libraries copied verbatim: 9 base fruit entries, 27 tier-formation entries, 72 gap/pressure entries, 27 tier descriptions/actions, report copy and tier guidance. Original tier-specific maturity, invitation, practice and prayer restored. User-written comments HTML-escaped.
- Existing linked DesignID primary/secondary included when available. Old completed reports are not regenerated or overwritten. Pre-existing native sessions retain their original instrument and report interpretation through versioned compatibility; new current-app sessions use the restored source contract.
