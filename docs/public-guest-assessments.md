# Standalone guest DesignID / DesignPD correction

Baseline: production checkout `2e621d9`, NOT the stale school-release checkout. Public purchases are separate from app accounts, courses and their existing assessment rights.

## Routes and ownership

- Website/public catalog → `/assessments/designid?guest=1` → guest name/email → exact $19.99 USD one-time Stripe checkout. No account is created; no signup/login, app membership or course grant.
- `/assessments/designpd?guest=1` explains the separate $19.99 derived report and directs an existing guest to their private DesignID recovery link. It never searches reports by an entered email. There is no second questionnaire.
- Public guest entry is forced with `guest=1`, including browsers already signed into the school. Existing plain `/assessments/{product}` URLs with real Auth retain the original account component, preserving account checkout returns, waivers, included access, source selection, report recovery/retry. The preserved component is the original `2e621d9` product page. Anonymous plain URLs also use the guest lane. Spiritual Gifts redirects to its unchanged existing `/spiritual-gifts` public experience.
- Four isolated `dydd_guest_*` tables contain guest sessions, orders, immutable results and payment reversals. None links to or writes Auth, profiles, participants, snapshots, account entitlements, course/progress/reflection or lifetime rows. Service-only RLS/grants; guest RPCs SECURITY INVOKER, empty search_path.
- Sessions own a random256bit capability, SHA256 stored in the session. Recovery validates exact session/hash/expiry, exchanges the query link for an HttpOnly Secure SameSite=Lax cookie and redirects to a token-free session URL. No-referrer/no-store/noindex headers cover the public routes. Session/report access uses no Auth identity or typed-email lookup. Recovery links are private bearer links, initially valid one year; expired links require receipt-based support reconciliation, not a new purchase.
- `?checkout=returned` is never payment evidence. The existing signed Stripe webhook dispatches `ownership=guest-v1` to a separate exact order/session/price/product/source verifier; current intent/charge must be successful and unrefunded/undisputed. SQL rechecks mode/tuple/reversal/source and serializes exact guest ownership. Existing account events retain their original handling. Refund/dispute revokes guest order and dependent exact-source PD access, never account rights.

## Canonical instrument and fulfillment

The existing20×4 integer0–3/exact5per-set questionnaire,12word clarification sort, scoring/presentation and report libraries are reused unchanged. Shared form defaults remain the app behavior; guest supplies a separate local draft namespace and guest-specific recipient/fulfillment copy. Saved guest results are isolated, immutable and unique per order. PD uses the exact paid completed guest ID and the existing derived engine/content version. No extra questionnaire, membership or course.

`dydd_guest_reserve_order` runs BEFORE Stripe creates a payable session. Guest-session/source partial unique indexes plus guest-session/email locks close double-click/concurrent reservations. Guest-only normalized-email history prevents pending/uncompleted purchase duplication and enforces six calendar months before a new guest ID purchase; it neither queries account identity nor provides report access by email. Eligible later retakes use a new guest session so original sources/reports remain intact. It does not attempt to merge guest history with an independently authenticated school identity or Gmail aliases.

Report preparation is an atomic CAS lease; the provider document ID is durably persisted before polling/archive/mail. Unknown provider creation outcomes are fenced for support, never retried as new PDFs. Known document retries poll/archive the ORIGINAL document. Stale creation recovery waits three minutes and requires a known ID. A ready immutable report is reused without charging/rescoring. The actual PDF is archived under private `assessment-report-pdfs/guest/{resultId}/report.pdf`; every download rechecks the unexpired guest capability and currently paid order/source before a short-lived signed URL.

Archive metadata is persisted BEFORE requesting report-ready email. Guest-specific copy has no school-login/Field Kit instructions. The existing immutable application outbox event `guest-report-{resultId}` provides idempotent retry; immediate sending and durable worker both recheck guest switch, exact link/capability/recipient, paid order/source and original archive, including a final pre-provider check. Confirmed revocation/expiry/foreign ownership is stopped; transient storage/configuration failures defer the SAME original event. Provider acceptance is distinguished from inbox delivery.
